# Great Voyage — P5 Water 아트·셰이더 시각 디자인 규격

- 문서 종류: **Water 디자인 명세**
- 스타일 목표: **Unity 2D Stylized Toon Water** — 탑다운, 다층 색면, 유기적인 파도 띠, 절제된 흰 포말
- 상태: **화풍 방향 승인** / 정확한 색상·파도 모양·애니메이션은 참고 비교 및 사용자 최종 수용 필요
- 연관 문서: `P5_OceanSystem_Design.md`, `P5_Water_References.md`, `P5_Water_ImplementationRoadmap.md`

## 1. 디자인의 핵심

사용자가 원하는 것은 단순히 "파란 배경이 움직이는 수면"이 아니라, **뚜렷한 색면과 곡선형 파도 형태가 겹쳐 흐르는 2D Stylized Toon Water**다. Unity 구현은 이 목표를 재현하는 수단일 뿐이며, 임의 Noise 애니메이션을 같은 장르라고 이름 붙이는 것으로 통과하지 않는다.

**최종 화면의 인상**

- 넓은 색면으로 구분되는 청색/청록색 바다.
- 화면 전체에 이어지는 크고 느린 파도 형태와, 그 위에 겹쳐지는 작고 약한 잔물결.
- 파도 마루에서만 자연스럽게 나타나는 흰색·연청록 포말.
- 곡선의 흐름과 색면의 덩어리가 유지되면서 유연하게 변형되는 애니메이션.
- 선박 주변에서는 같은 수면 아트 언어를 유지한 채 선수 분기·선측 흐름·선미 항적이 나타남.

## 2. 시각 요소별 강제 규칙

| 요소 | 표현 규칙 | 피해야 할 결과 |
|---|---|---|
| **Base Water** | 다단계 청색·청록색 색면, 깊이/환경에 따른 색상 차이 | 단색 파란 판, 사실적 거울 반사 |
| **Large Wave Shapes** | 흐름 방향을 가진 넓고 불규칙한 유기적 곡선/띠 | 단순 원형 Noise 얼룩, 딱딱한 격자 |
| **Secondary Ripples** | 큰 파도와 규모·속도가 구분되는 작고 약한 잔물결 | 모든 패턴이 같은 속도로 반복 |
| **Wave Crest Foam** | 파도 마루를 따라 끊겼다가 이어지는 비균일한 흰/연청록 곡선 | 무작위 흰 점만 뿌림, 동일 두께의 평행선 |
| **Hull Foam** | 선수 충돌점에서 시작해 선측에 맞게 분기/흐름 | 선체 형태와 무관하게 전역 포말 재생 |
| **Wake** | 선미 뒤쪽으로 퍼지며 희미해지는 분기·난류·포말 | 선박 뒤에 고정된 단순 하얀 삼각형 |
| **Particles** | A 미세 비충돌 입자와 B 충돌·분열 물보라가 각자 규모/역할을 가짐 | 모든 입자에 같은 거동 적용 |

**색상 처리:** 시작안으로 밝기/톤이 구분되는 **3~5단계** 색면을 권장하되 숫자와 RGB/HSV값은 확정된 사용자의 색상 팔레트가 아니다. 최종 값은 실제 Game View 비교 후 고정한다.

**형태 처리:** Noise는 곡선의 변형·파열·경계 흔들림을 만드는 보조 재료다. Noise 생성물이 물결의 최종 형태를 전부 대체해서는 안 된다.

## 3. 셰이더의 시각적 레이어

아래 레이어들은 논리적으로 독립 조절 가능해야 하되, 실제 Shader Graph 노드나 Pass 수를 강제하지 않는다.

1. **Base Color Ramp** — 바다의 기본 색상과 수심/환경별 색조.
2. **Large Wave Pattern** — 넓은 유기적 파도 색면. 주 흐름과 곡선을 읽을 수 있어야 한다.
3. **Secondary Ripple Layer** — 잔물결의 세부 움직임, 큰 파도보다 약한 대비.
4. **Crest Foam Mask** — 파도 마루와 일부 강한 물결에 붙는 곡선형 포말.
5. **Ambient Animation** — 항해 속도가 0이어도 존재하는 자연 물결의 고유 운동.
6. **Relative Flow** — 항해 방향·속도에 따른 **표면 패턴의 상대적인 움직임**.
7. **Hull-Aware Local Deformation** — SDF/형상 기반 선수 분기, 선측 흐름.
8. **Wake & Interaction** — 선미 후류, 국소 포말, B 입자 충돌·분열.
9. **Lighting Extension (후속)** — 승인된 파도 형상에서 도출 가능한 법선·기울기와 별도 광원 파라미터로 명암·하이라이트를 계산하는 후속 계층. **기본 Water 스타일 단계의 구현 대상이 아니다.**

**동기화 규칙:** 바다 타일의 Transform을 돌리는 대신 모든 타일이 공통 시간·좌표계·흐름 데이터를 사용한다. 타일 경계에서 파도와 포말이 끊기면 실패다.

## 4. 움직임과 상태별 요구

| 상태 | 보이는 효과 |
|---|---|
| **정지** | 큰 파도/잔물결의 자연 애니메이션은 지속. 이동 속도 기반 물살·물보라는 없음/잔여분 감쇠 |
| **전진** | 큰 파도 색면·포말의 상대 흐름이 선박의 이동 반대 방향으로 나타남 |
| **가속/감속** | 상대 유속·선체 접촉 포말·항적 강도가 변화. 급격한 시각적 튐 방지 |
| **방향 전환** | 타일 Transform 회전 없이 물결 흐름 벡터 및 선체 상호작용이 함께 변경 |
| **선수 충돌** | 선체 앞에서 유동이 양쪽으로 갈라지고 밝은 포말/물방울이 발생 |
| **선측** | 선체의 실제 윤곽을 따라 곡선 흐름과 국소 포말 표현 |
| **선미** | 후류가 뒤쪽으로 퍼지면서 길이·밝기·밀도가 점차 줄어듦 |

참고 이미지의 정지 장면은 **형태·색감·구도**에 대한 참고이지, 움직임이 자연스럽다는 증거가 아니다. 실제 연속 영상/실조작 평가를 별도로 수행한다.

## 5. 승인되지 않은 임의 해석 금지

- **3D 물리 파도/PBR 수면/사실적 물결** 중심의 화풍으로 바꾸지 않는다.
- 강한 반사·굴절·네온 발광·사진 질감·과도한 노멀맵 느낌을 기본값으로 추가하지 않는다.
- 바다 타일·배경 Sprite를 회전/이동하여 항해를 표현하지 않는다.
- **색면·파도 띠가 식별되지 않는 랜덤 Noise 스크롤**을 목표 스타일이라고 선언하지 않는다.
- 기본 Water Shader 결과가 부족한데 파티클/물보라를 더해 품질 부족을 감추지 않는다.
- 참고 이미지를 **제품 텍스처나 그대로 복제할 필수 정답**으로 취급하지 않는다.
- 생성된 컨셉 이미지의 선박 형태·돛·UI를 **확정된 기존 게임 에셋 설계**로 간주하지 않는다.
- 기본 해수 화풍을 다른 프로젝트의 자산 스타일로 임의 대체하지 않는다. 기존 `Agents/VisualStandards.md`의 선박/항구 아트 스타일과 조합해 최종 판단한다.

## 6. Water 디자인 승인 단계와 조명 분리

해수의 기본 시각 결과를 먼저 **조명이 없는 상태**에서 판단한다. 정적 모양과 자연 애니메이션은 Stage 2에서 순서대로 승인한다. 해수 상대 흐름(Stage 3), 선체 상호작용(Stage 4) 후에 별도 Stage 5로 **수면 조명·반사 표현**을 추가한다.

- **기본 스타일 승인 대상**: 물의 색면 경계, 큰 파도 띠, 잔물결, 자연 포말, 패턴의 시간 변화 및 Seamless 타일 동기화. 실제 입체 조명/Specular/실시간 반사를 섞어 외형 부족을 가리지 않는다.
- **후속 조명 승인 대상**: 파도의 기울기에 따른 명암, 태양 방향·색상·세기, Toon 스타일을 해치지 않는 선택적인 Specular·하이라이트. 조명 효과는 기본 물결의 흐름·형태를 변경하지 않아야 한다.
- **분리 검증**: 동일한 장면/항해 상태에서 Lighting Off/On을 비교하고, Off에서는 사용자 승인된 기본 Water와 같은 화면으로 복귀할 수 있어야 한다.
- **개발상 분리와 데이터상 연결의 구별**: 광원 연산은 늦게 구현하되, 초기 물결의 공간 좌표·시각적 형상 정보를 후속 법선 도출에 이용할 수 있도록 책임 경계를 확보한다. 아직 법선 계산 방식이나 높이장을 확정하지 않는다.

## 7. 실제 Game View 승인 절차

**1단계 — 정적 Water 스타일**

- 배·HUD·입자를 빼고 바다 화면만 제시한다.
- 기본 색면의 수와 명도 차이, 큰 파도 띠 곡선, 작은 잔물결, 불규칙한 포말 마루를 확인한다.
- 기존 게임 Sprite와의 색감·선 두께·디테일 밀도 비교 후 사용자 승인.

**2단계 — 기본 Water 애니메이션**

- 파도의 큰 형태가 유지되면서 흐르고 변형되는지 확인한다.
- 반복·줄무늬·너무 빠른 노이즈·타일 경계·UV 이음새 등을 확인한다.
- 정지 상태 자연 물결이 정상인지 확인 후 사용자 승인.

**3단계 — 상대 운동**

- 해수 패턴의 방향·속도를 항해 상태와 연결한다.
- 정지/전진/가속/감속/방향 변경 시 원래의 Toon 화풍이 깨지지 않아야 한다.

**4단계 — Hull-Aware 효과 및 입자**

- 선체별 WaterlineShape와 SDF로 선수 분기·선측 물살·선미 후류를 연결한다.
- A 비충돌 입자와 B 충돌 입자를 구분한다.
- 국소 포말/물보라가 **기본 Water 디자인을 덮어 가리지 않는지** 검수한다.

**5단계 — 수면 조명(독립 승인)**

- 기본 Water Shader가 승인된 뒤에만 조명을 추가한다.
- 조명 On/Off 비교로 파도 형태·색면·움직임의 보존 여부를 판정한다.
- 현실적인 광학 계산의 일부 원리를 참고할 수 있으나 결과는 일관된 Toon 화풍을 유지해야 한다.
- 실제 반사·굴절·3D 파도를 임의로 추가하지 않는다.

**6단계 — 통합 및 안정성**

- 다양한 선체, 해상 상태, 타일 경계, 저장 복원, 성능과 최종 Game View에서 이전 승인 품질이 유지되는지 점검한다.

## 8. 실제 튜닝을 위해 노출할 설정

| 시각 파라미터 | 역할 |
|---|---|
| Water Palette / Color Steps | 기본 물색·색면 단계 |
| Major Wave Scale / Contrast | 큰 파도 폭·강조 정도 |
| Ripple Scale / Strength | 잔물결 크기·강도 |
| Crest Foam Coverage / Breakup | 파도 마루 포말의 양·끊어짐 정도 |
| Ambient Motion Rate | 자연 물결 애니메이션 속도 |
| Relative Flow Strength | 항해에 따른 상대 시각 속도 |
| Hull Flow Radius / Deflection | 선체 영향 영역·분기 강도 |
| Bow Foam / Side Foam / Wake Length | 충돌 포말·선측 포말·후류 강도/범위 |
| Particle Density / Collision Response | 입자 수·충돌 반응의 시각적 강도 |
| Lighting Enabled / Sun Direction / Highlight Strength | **Stage 5 전용** 광원 On/Off·방향·하이라이트 조절 |

수치·셰이더 식·Texture 해상도·모든 노드 연결은 현 프로젝트와 시각 검증을 바탕으로 선정하며, **현재 문서가 확정하지 않는다.**

## 9. 판정 기준

**통과**는 정지 이미지의 분위기 유사성만이 아니라, 실제 Unity 2D Game View에서 **뚜렷한 Toon 색면, 유기적인 파도 형태, 분리된 자연 물결/상대 흐름, 경계 없는 공통 셰이더, 선체 주변 일관된 포말**을 확인하고 사용자 승인을 받은 상태를 의미한다.

**미통과**는 기본 물결이 Noise 얼룩/스크롤만으로 보이거나, 타일 경계가 드러나거나, 파티클 추가로만 그럴듯해지는 경우다.


## 10. 스타일 승인 시 에이전트 제출 형식

- **정적 스타일**: 선박·파티클·조명 없는 동일 구도의 Game View 이미지, 파도와 포말 레이어별 확인 화면.
- **자연 애니메이션**: 시작·중간·종료가 포함된 연속 화면 또는 짧은 영상. 타일 경계 및 이동 양상을 확인 가능해야 함.
- **상대 흐름**: 동일 스타일에서 정지/전진/가속/감속/방향 변경 화면 및 항해 속도/방향 표시.
- **선체 상호작용**: 선수·선측·선미를 구분한 결과, 두 입자 유형을 따로 확인할 수 있는 화면.
- **조명**: 동일 조건 Off/On 대응 화면, 빛 방향 변화에 따른 법선 반응, 기본 스타일 보존 근거.
- 참조 이미지를 기준으로 **무엇이 동일하고 무엇이 다른지** 근거 있는 대조표를 작성한다. 구현 방식이 참고 이미지와 비슷하다는 설명만으로 완료하지 않는다.
